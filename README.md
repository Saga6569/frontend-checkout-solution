# Checkout — интернет-магазин на React + TypeScript

Интерфейс магазина: каталог, корзина, оформление заказа и оплата. Фронтенд — React 19 + TypeScript + Vite (`apps/web`), бэкенд — Node.js (`apps/api`), монорепозиторий на npm workspaces.

Документация: [Условия](docs/ASSIGNMENT.md) · [Работа с API](docs/INTEGRATION.md) · [Критерии](docs/EVALUATION.md)

## Запуск

Потребуются Node.js 24.x и npm 11.x. Отдельная база данных и ключи внешних сервисов не нужны.

```sh
git clone https://github.com/Saga6569/frontend-checkout-solution.git
cd frontend-checkout-solution
npm ci
npm run dev        # API на :4000
# в другом терминале:
npm run dev:web    # фронтенд на :3000 (проксирует /api → :4000)
```

Swagger: [http://localhost:4000/docs/](http://localhost:4000/docs/). Спецификация: [http://localhost:4000/openapi.json](http://localhost:4000/openapi.json) или [файл в репозитории](docs/openapi.json).

В Swagger выполните `POST /api/sessions` с телом `{}`. Скопируйте `data.token` в **Authorize**, без слова `Bearer`.


## Проверки

```sh
npm run check       # форматирование, сборка, тесты и OpenAPI
npm run build
npm start           # запуск собранного бэкенда
```

При работающем API в другом терминале выполните `npm run smoke` — проверяет покупку, отказ карты, отмену и повтор оплаты по HTTP.

## Настройки

Адрес по умолчанию — `127.0.0.1:4000`. Если порт занят, скопируйте `.env.example` в `.env` и измените `PORT`. Данные сохраняются в `.data/store.json`; для сброса остановите сервер и выполните `npm run data:reset`, затем создайте новую сессию.

## Архитектура фронтенда

### Работа с API

Весь HTTP-транспорт сосредоточен в одном месте: `src/api/client.ts`. Функция `request<T>()` принимает путь и `RequestInit`, подставляет базовый URL, заголовок авторизации, парсит JSON и при ошибке выбрасывает единый `ApiError` с полями `code`, `message`, `fields`. Компоненты не вызывают `fetch` напрямую и не проверяют `response.ok`.

Типизированные вызовы API описаны в `src/api/endpoints.ts` — каждый вызов передаёт только path и init в `request()`. Для идемпотентных операций (создание заказа, оплата) ключ генерируется через `crypto.randomUUID()` и передаётся заголовком `Idempotency-Key`.

### Состояние приложения

Единый `AppContext` (`src/store/AppContext.tsx`) хранит: текущую страницу, корзину, каталог, расчёт, заказ, платёж. Все обновления проходят через него. Сессия (token, orderId, paymentId) persistится в `localStorage` и восстанавливается при перезагрузке.

### Ошибки и повторы

`ApiError` создаётся в одном месте (`client.ts`). Хук `useAsync` оборачивает любую async-функцию, отслеживает loading/error и отбрасывает устаревшие ответы через sequence counter. Polling реализован в `usePolling` — останавливается при unmount и при возврате `true` от fetcher.

### Пример обработки данных: `formatMoney`

`formatMoney(kopecks)` вызывается при каждом рендере карточки товара, позиции корзины и строки расчёта. Функция делает один вызов `Intl.NumberFormat.format()` — O(1), без промежуточных массивов или копирований. Для каталога из N товаров — N вызовов, каждый линеен по числу цифр (константа). Ссылка на форматер кешируется движком V8 внутри `Intl`.

### Проверенные сценарии

- Каталог → добавление в корзину → изменение количества → удаление
- Оформление: самовывоз и курьер, пересчёт при смене доставки
- Оплата картой: success, decline, cancel; повтор после отказа
- Наличные при получении: заказ без онлайн-оплаты
- Восстановление сессии после перезагрузки

### Известные недоработки

- Нет клиентской валидации формы перед отправкой (только серверная)
- Нет анимаций переходов между страницами
- Адрес пункта выдачи показывается как ID, а не как человекочитаемое название
